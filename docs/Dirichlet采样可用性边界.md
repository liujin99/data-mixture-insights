# Dirichlet 采样可用性边界：proxy 配比实验的混合采样问题（多证据交叉分析）

> **起因**（2026-11-09）：用户指出 CLIMB（#74）用 Dirichlet 采样且配比优化有效（一手复现同向），与 LinMix（#146）"Dirichlet 出局"表面冲突。本文把两边证据对齐口径摆开，给出结论的准确边界与实操判据——**结论不是"Dirichlet 采样失效"，而是"可用性随维度与 prior 形状退化"**。定位：协议层交叉分析，与 #70/#124/#146 三处收敛的准确表述。

## 一、问题定义

proxy 配比搜索（RegMix/CLIMB/Olmix/LinMix 同族）：训 m 个小 proxy 模型、各喂不同混合、回归拟合"混合→性能"、挑最优混合。**混合怎么采样**＝设计矩阵 Π 怎么选＝经典回归实验设计问题（Kiefer-Wolfowitz 1959）。Dirichlet 采样是行业事实默认（RegMix/Olmix/CLIMB 全在用）。

## 二、两边证据（对齐口径）

### 正面：Dirichlet 有效

| 场景 | 域数 | proxy 数 | 采样 | 结果 | 来源 |
|---|---|---|---|---|---|
| **CLIMB** | **20-21 语义簇** | 112 次搜索（3 轮 64/32/16 迭代闭环） | Dirichlet（**按簇 token 数初始化**，消融 60.41 vs 均匀 60.21） | 配比优化有效（超 DoReMi/RegMix）；簇数甜点 ~15-30 | #74，NVIDIA，NeurIPS'25，T1 + **用户一手复现同向** |
| LinMix 24 域 | 24 | 512 | Dirichlet（默认+调参均可） | **两种采样下所有 surrogate（线性/LightGBM/指数）都拟合良好**；顶点仅略优（ARC +2.8%、CPile 还略输 RegMix） | #146 **自证** |
| RegMix / Olmix | 各自粗域设定 | — | Dirichlet | 均有正结果（Olmix ICML'26 为 LinMix 的 SOTA 基线之一） | #36/#155 |

### 反面：Dirichlet 失效

| 场景 | 域数 | proxy 数 | 采样 | 结果 | 来源 |
|---|---|---|---|---|---|
| LinMix 288 细域 | **288**（topic×format 细粒度） | 1024 | Dirichlet 默认（τ=2, γ∈[0.1,5]） | **连采样都不收敛**（cap 违约拒绝循环） | #146 Fig.2 |
| 同上 | 288 | 1024 | Dirichlet 调参（条件数最小化→γ∈[40,4000]） | **任何 surrogate ρ≤0.39**；对照：顶点+线性照常工作、**512 个顶点 proxy 胜过 1024 个 Dirichlet proxy** | #146 Fig.3 |

### 机理（Theorem 1，两个失效因子相乘）

1. **贴 prior 欠分散**（γ 大→样本聚在 prior 附近）：proxy 结果方差坍缩——贴 prior 的 Dirichlet 混合使 HellaSwag BPB 变动比顶点设计**小 5×**，回归没有信号可学（误差 1/c 因子）
2. **尾部饥饿**（prior 偏斜时）：小域几乎拿不到非零权重→小域归因不可辨识（误差再乘 d^(p−1) 因子，p=Zipf 尾指数/τ）

## 三、为什么不矛盾：三个边界变量

1. **维度 × prior 形状的乘积效应**：CLIMB 的 20-21 簇是**聚类产物**——簇间 token 量相对均衡（p 小），Dirichlet 样本能有效铺开单纯形；WebOrganizer 的 288 细域 prior 重 Zipf 尾（p 大），两个失效因子同时命中。**失效不是单一域数阈值，是 d×偏斜度的联合条件**
2. **目标结构不同**：CLIMB 的目标是**找好混合**（优化），且用**迭代闭环**（每轮 LightGBM 用全部历史重训+预测器剪枝、只训 top 候选）——闭环本身就是信息效率补偿，低信息样本也能被循环利用；LinMix 288 域的目标是**一次性恢复 288 个归因系数**（全局辨识）——可辨识性要求严苛得多。**同样的采样，优化目标下够用、归因目标下不够**
3. **单 run 信息量而非 run 密度**：CLIMB 112/21≈5.3 run/域、LinMix 24 域 512/24≈21、288 域 1024/288≈3.6——但"一半顶点群胜全量 Dirichlet 群"说明差别在设计质量而非数量

## 四、实操判据

**分级**：

| 域数层 | 建议 | 依据 |
|---|---|---|
| **≲24-30 域**（聚类产物、prior 相对均衡） | Dirichlet 可用；初始化按 token 数；迭代闭环（CLIMB 式）信息效率更高 | CLIMB 一手证据+LinMix 自证双确认 |
| **~30-100 域** | 无直接证据（两侧外推均可）——靠预警信号判 | 证据空档 |
| **≳100 域**（尤其 prior 长尾） | 换经典设计：**顶点采样**（LinMix Greedy fill+配对反向排列，定主效应）+**内部/轴向点**（#70 Scheffé，测交互）；或两阶段（粗层 Dirichlet 定方向→细层顶点做归因） | LinMix 288 域崩+Theorem 1 |

**失效预警信号**（三个都可在线监测）：

1. **采样 cap 违约率**——拒绝循环＝超参失效（LinMix Fig.2 的直接观测）
2. **proxy 结果方差坍缩**——各混合的 BPB/loss 极差缩水＝"没信号可回归"（LinMix 的 5× 信号比观测）
3. **设计矩阵条件数**——LinMix 用条件数最小化反推 γ 调参，本身就是打补丁的信号

**与 #124 正交**：重复率失配（proxy 与 target 的 epoch 结构不一致）是独立失效源——换了顶点设计后**仍须单独过** #124 的子采样匹配。

## 五、库内定稿表述

- 原 §31/LinMix 深读初版的"**Dirichlet 出局**"（2026-11-09 深读当日措辞）修正为：**"Dirichlet 可用性随维度退化：粗簇层（≲24 域）实战有效（CLIMB 一手证据+LinMix 自证），100+ 细域定理级崩（Theorem 1）——细簇参数化时的采样警告，非普适否定"**
- **三处收敛（#70/#124/#146）的准确含义**：不是"Dirichlet 采样失效"，而是"proxy 混合实验的设计问题在三个正交轴上分别有经典统计解"——**#70 治交互建模**（Scheffé 多项式+I-最优设计）、**#124 治重复率失配**（子采样匹配 epoch 结构）、**#146 治高维采样**（顶点设计恢复可辨识性）。三者正交、可叠加；粗域场景三个都不必然触发

## 六、方法论沉淀

用户 CLIMB 一手经验在本次修正中的角色：**一手反例是划定论文结论适用边界的最高效手段**（"一手复现 > 论文自报"准则的又一兑现）。值得注意的细节：LinMix 的 24 域实验**自己就包含**"粗域 Dirichlet 无碍"的数据点，但被"Dirichlet 崩"的叙事盖过——**读方法论文时先核对它的实验粒度是否覆盖自己的场景区间，再决定结论适用与否**；论文标题级结论（"Dirichlet is a poor design"）与它的分区数据（24 域持平）之间的落差，正是用户一手经验能插进去的地方。
