# daVinci-Prover（GAIR）Agent-Native 中训练深度分析

> arXiv 2611.16433v1（2026-11-12）| GAIR（Generative AI Research Lab）+ 上海创新研究院 + 上海交大 + 复旦，**Pengfei Liu 通讯** | 总表 #165 · T2 **[高价值]** | 2026-11-16 用户裁定深读 | 底档 /tmp/opencode/dvp.html（211KB，全文 5.4 万词符）

## 1. 一句话与定位

定理证明垂直域的**完整透明中训练配方**：33.7B token agent-native 语料（技能先验 84.8% + 语料内回放 15.2%）+ 36K verifier-grounded 轨迹 SFT，配比/管线/成本/消融全披露。**库内定位：#161《An Open Midtraining Recipe》同哲学（技能先验+轨迹喂 MT、SFT 桥评测）在单一垂直域的学术复刻，且尺度（8B-9B base + 33.7B MT）比 #160/#161 的 Lightning 200-500B 全域 MT 更接近用户 3B-A1 场景——"抄得动"的直接参照。**

## 2. 核心主张：中训练装什么

- 论点：好用的 agentic prover 需要两样东西，都不该留给 post-training——① **数学技能先验**（分解/搜索/自验/修正），② **环境原生轨迹**（工具调用、执行结果、Lean 反馈）。全部经 MT 喂入。
- 机制名目：**分布对齐**（agent 数据让静态 NTP 训练分布贴近交互推理分布）+ **先验植入**（技能数据给可复用推理底座）。消融证明两者**互补不互替**（§7）。

## 3. 33.7B 配比表（Table 1 全文——本文最有"工业实战精选"味道的一张表）

| Self-verification（自验，含 meta-verification） | 0.083 | 5.70 | 16.9 |

- 样本/token 反差：agent 轨迹只 0.4M 样本却占 21.3% token（长轨迹）；自验 0.08M 样本占 16.9%——**"少样本高 token"是轨迹类数据的共性**。
- **Replay 细节**（与 NVIDIA PT 回放同族但对象不同）：按"期望配比"给各源设回放预算、源内质量分选优、**先覆盖不同题再允许同题多轨迹**（多样性优先规则）；回放对象=32K 语义分块前的完整父轨迹。NVIDIA 20% 回放的是原始 PT 语料（防遗忘），本处 15.2% 回放的是自家语料精选（质量强调）——**"回放"一词两义，引用时须分清**。
- 语料底池：NuminaMath-LEAN、AoPS、Lean Workbook、Goedel-LM/SFT_dataset_v2、OProofs；Qwen3.5 tokenizer 计数；32K 语义边界分块；去污仅删 0.034%（去重+评测集排除——卫生纪律样本）。

## 4. 数据合成管线：教师=别家开源模型

- 教师：**DeepSeek-V4-Flash + V4-Flash-0731**（284B-A13B，部署 48×H200×20 天）——与 3 Ultra MOPD"数据引擎大量用别家开源模型"同款模式的学术侧复刻。
- 四条合成线：分解轨迹（参考证明→自然语言计划+辅助引理+组装）；子目标搜索（回放已验证证明抽中间态，提案模型生成多 tactic 同快照独立执行，保留成功闭合/开放态/**Lean 报错**——**报错也是数据**）；修正轨迹（四字段结构化诊断：location/symptom/cause/fix+修正计划）；非形式推理（**直接用 NVIDIA Nemotron-Math-Proofs-v2** + DeepSeekMath-V2 式提示：证明生成/自评/验证/meta-验证——**NVIDIA 数据资产被第三方采用，资产线活样本**）。

## 5. Harness 与 SFT 数据纪律

- daVinci-Prover harness（GitHub 开源已核，5★ 新仓）：edit-check-revise 循环，7 工具，scratch/（可写）/sketch/（分解草稿）/target/（只读 Lean/Mathlib 项目）三目录；成功判据=严格验证+声明与 elaborated type 匹配原文。
- SFT 轨迹采集：Goedel RL_dataset_v2（~99K 未验证题）采样；**30 turn/200 tool call 上限**、过滤 <5 turn、≤144K context、剔过度重复/无效工具调用——轨迹质量纪律与 #161"轨迹封顶"同族。
- 产出 36K 高质量成功轨迹（9 个数学域全覆盖）。

## 6. 训练配方（附录 G）

- 目标：全参 NTP + **保留单层 MTP（loss 权重 0.1）**；MoE **保留 PT routing 配置**+aux load-balance 1e-3——"MT 不拆 PT 结构性目标"的又一样本。
- LR：3% warmup + **cosine decay 到 0**（衰减营；与 NVIDIA reset-constant〔#161〕、GLM-5 连续线性衰减并立——三营再添一员，同为衰减侧但函数不同）。
- 32K offline packing + **样本级隔离**：块对角因果注意力、位置索引重置、**Gated DeltaNet 状态重置**（线性注意力混合架构的 packing 卫生细节，可抄）。
- **无长上下文课程**：32K 文档训练 + YaRN 32K→256K 外推——与 #161 的 RULER 恢复段路线不同（本配方用 rope 外推解决，省一整个 LC 段）。
- 评测纪律：Lean v4.26 + Mathlib pin commit；**拒绝 axioms/local instances/native_decide**（证明层反作弊，与 NVIDIA SWE 教师 RL 反作弊同族）；pass@1 三次平均；temp 1.0。

## 7. 实验与消融（含批判挑刺）

- **headline +13.7 的真实边界（最重要的挑刺）**：+13.7 平均分是 **Qwen3-8B（旧 base）** 上的（73.4/68.0/28.4→85.3/85.3/40.4，MiniF2F/FATE-M/ProofNet）。在 **Qwen3.5-9B** 上增益收敛到 +1.3~+3.0（MiniF2F 92.6→93.9、MathOlympiad 32.3→35.3、Putnam 22.3→24.9），**35B-A3B MoE 上更小**（+0.3~+2.2）——**base 越新、底子越好，域专项 MT 边际收益越小**。给 3B-A1 的校准：若底座已含优质数学/代码数据，MT 增益按 +1~+3 级预期而非 +13 级；大增益数字多出现在"旧/弱 base + 新配方式"组合里（对 #160 Lightning 同理需谨慎）。
- **消融（Table 4，Qwen3.5-9B）**：D_skill 单独（25.3B）+0.4/+1.4/+0.7；**D_agent 单独（8.4B）+1.4/+3.8/+0.6——1/3 的 token 产生更大增益**；组合 33.7B +2.7/+4.9/+1.6 全场最优。结论：**分布对齐>知识灌输**，且互补不互替。这是"轨迹数据应计 token 而非按样本配额"的直接证据。
- **语料对比（Table 5，Qwen3-8B）**：本语料 33B token > OProver 65B token（85.3 vs 80.3 MiniF2F）——"MT 效果取决于构成而非规模"的直接对照。
- **Scaling（6.3，7.5/15/22.5/30/33.7B 五点）**：近似 log-linear；**前 15B 吃掉大部分增益**（MiniF2F +3.96、FATE-M +11.11），后段收益缩水——域专项 MT 的剂量收益递减曲线，15B 级是性价比甜点。
- **训练过程（6.1）**：midtrain ckpt 起 SFT loss 即更低、1 epoch 即匹配 base 5 epoch 的 pass@5——"MT=更好的初始化"的过程证据（#160"MT 装知识/格式、行为归 post-training"的学术验证）。
- **行为改变（6.2）**：midtrain 后早期工具参与更强、file_write 前移（更早开始构造文件）、难题分解步数趋近教师 DSv4-Flash——行为层证据链。
- **Memory compact（6.6，推理期非训练数据）**：200K 处触发"旧交互→确定性抽取的工具证据"压缩（≤8 次）：FATE-H 16.7→28.0（9B）/16.3→**42.0**（35B）、MiniF2F 90.1→97.1。**诚实记录：上下文管理的杠杆（+11~+26 分）比 MT 本身（+1~+3 分，新 base 上）大一个量级**——长程任务里"喂多少轨迹数据"不如"推理时怎么管理上下文"。对 3B-A1：轨迹数据预算与上下文压缩设计应一体考虑。
- **协议不对齐**：Table 2 用自家 pass@8 对比同行标 † 的 pass@32（未自重评）——大模型比较（DSv4-Flash vs 专业 prover）不严格对齐，仅"量级参考"；9B/35B 增益行是自家协议内对比、可信。
- 单一垂直域验证（数学证明）；单 run 体系（pass@1 三次平均但无方差报告）；无 venue（11-14 挂出）。

## 8. 成本账（附录 F——域专项 MT 的现实定价）

- 教师 48×H200×20 天≈23,040 GPU 时（含失败/丢弃/空闲），公允租价折 **$122K-146K**；Lean 验证 CPU 160 核×20 天另计。
- 含义：8-9B 级域专项 MT 的**全部数据合成成本≈15 万美元级**——比训练本身（33.7B token×8B 全参）更高。3B-A1 若走此路线，数据合成是主要开销项，须先按 §7 增益预期做 ROI 判断。

## 9. 库内连线（九条）

1. **#161 三明治/SFT 桥**：同哲学同纪律（matched Base+SFT 对照、轨迹封顶、防作弊）——垂直域学术版。
2. **#160"MT 装知识/格式"**：6.1 过程证据直接支持；旧 base 大增益 vs 新 base 小增益=先验存量决定边际。
3. **手册"RL/MOPD 配比"与 3 Ultra MOPD**：教师=别家开源模型（DSv4-Flash）、报错也是数据、轨迹质量过滤——学术侧同款数据引擎。
4. **Nemotron-CC-Math/资产线**：Nemotron-Math-Proofs-v2 被直接采用为非形式推理组件——NVIDIA 数据资产的第三方采用实录。
5. **回放 15.2% vs NVIDIA 20%**：同族不同义（语料内精选回放 vs PT 防遗忘回放）——手册"MT 配比"行补注对象之别。
6. **LR 三营**：cosine→0（本篇）加入衰减营，与 NVIDIA reset-constant、GLM-5 线性连续并立——衰减侧内部函数也不统一，实证支撑"衰减方向收敛、函数形状未收敛"。
7. **MTP/routing 保留**：MT 保留 PT 结构性目标（MTP 0.1、routing+aux 1e-3）——与 3 Ultra MTP/结构性继承互证。
8. **#52 容量竞争/旧 base 效应**：35B-A3B 增益最小与头部挤压一致——大模型/新 base 域专项 MT 收益天然小。
9. **#112 SFT 翻转中训练**：本篇 SFT 是同域（证明）5 epoch——若异域 SFT 是否翻转未测，引用时注意。

## 10. 对用户场景（3B-A1 MoE STEM MT）的引用清单

1. **剂量**：域专项 MT 15B 级甜点、33B 见顶（8-9B base 上）——3B 激活的域专项剂量按比例 ≈5-15B token 级预期。
2. **配比骨架**：分解 25%/轨迹 21%/自验 17%/回放 15%/修正 11%/搜索 10%——可直接当 STEM 版 agent-native MT 的初始配比模板。
3. **轨迹数据按 token 配额**（D_agent 8.4B>25.3B D_skill 的增益效率）。
4. **教师选择**：用最强开源教师（别家的）合成数据完全可行且被 NVIDIA/本篇两端验证。
5. **上下文压缩 > 加轨迹**（新 base 上）：预算优先给推理期压缩设计。
6. **packing 卫生**：样本隔离+线性注意力状态重置细节。
7. **成本门槛**：~$15 万级数据合成预算（9B 规模教师路线）；3B 规模按比例低。
8. **LR**：cosine→0 可作衰减营缺省选择。

## 12. 结论

**深读判定：T2 维持**（无 venue+学术规模堵 T1；透明度/消融/纪律全优，非 T3 级"待验证"）。价值不在 +13.7 的 headline，而在：**① 唯一一份"配比表级"透明的域专项 agent-native MT 配方（尺度最接近用户场景）；② 三条校准律——agent 轨迹按 token 计价/前 15B 甜点/新 base 上增益收敛至 +1~3 级；③ 成本账 $15 万级。** 不入"工业实战精选"分栏（学术规模、未进生产），但作为 ①席位（3 Ultra）与 ②席位（3.5+Singhal）之间的"可抄尺度参照"挂在边界注记。下一步触发器：语料/轨迹开源兑现核验、venue 落地（ICLR/NeurIPS 投稿线）。

## 13. 用户三问三答（2026-11-16，补录）

**Q1 教师=DeepSeek-V4-Flash 会不会太弱？** ——不是圈内最强选不起，是"可自部署的最强"。同 harness 下开源圈实测第一（MiniF2F 95.9 pass@8 超全部专用 prover；Qwen3.6-35B 仅 68-73）；但承认更强闭源系统（Seed-Prover 1.5/Hilbert）未发布或跑不起、未对比。选它=NVIDIA MOPD 同款逻辑：**开源+可自部署（48×H200×20 天）+合法产出可发布轨迹**（闭源 API 不能拿来发数据）。教师弱的天花板在难题可见：学生 MathOlympiad 35 vs 教师 52、Putnam 25 vs 40——差距没收回。

**Q2 训出来的模型什么水平？** ——9B 学生进开源第一梯队：超 32B 专用 prover（MathOlympiad 35.3 vs OProver-32B 22.8、ProofNet 52.7 vs 33.2、Putnam 24.9 vs 11.3）、与 560B LongCat sketch-proof 模式互有胜负（Putnam 略输 24.9 vs 28.9）、逼近教师（MiniF2F 93.9 vs 95.9——4/5 榜达教师 90-98%，唯难题榜 ~65-70%）。加 memory compact 后 MiniF2F 97.1、FATE-H 42（35B）为断层水平（基线普遍 4-19）。协议注：学生 pass@8 对同行†pass@32——采样更少仍胜，方向对学生不利、可信度加分。

**Q3 只公布最终配方还是连找法一起公布？** ——**只公布最终配方，配比的找法就是手调**。原文 "assign each source a replay budget **according to the desired data mixture**"——期望配比预设，六类百分比（25/21.3/16.9/15.2/11.4/10.2）无任何搜索/网格/优化过程披露；事后验证仅两层粗消融（skill vs agent 两分法 §6.4+总量 scaling §6.3），无六类逐项配比实验。**"数据怎么造"全公开（四条合成线+harness 开源），"配比怎么定"手调+事后消融**——为手册"定比例=手调+消融+护栏"再添学术侧实证：连最透明的配方论文也不搜配比。

## 14. 价值重估：没有"定配比方法"的前提下，它对我们是什么（2026-11-16 用户追问；同日二次修正）

**定位前提（修正版）**：用户两问逼出两处修正——① **"定配比的方法在公开世界不存在"系滑坡**：正确表述是**未披露/不可观测，而非不存在**（头部厂商做 15T/27T 决策必有内部方法学；分栏局限①"沉默厂商不可观测"才是正确姿势）。且"方法"须拆两半：**验证方法学已披露可抄**（消融/回归护栏/SFT 桥/回放规则——手册抄的正是这半），**决策方法学在沉默区**（候选生成/判据/迭代函数未披露）。② **"种子模板"不能指数字**：六类百分比绑定其池（五源+自家合成管线）、其域（Lean 交互长→轨迹 21.3%）、其 base（Qwen3.5）——换池即作废，"不能直接抄"。

**可迁移性分界表（daVinci 版，对齐 #161 §8.1）**：

| 成分 | 可迁移性 |
|---|---|
| 六类分类法（技能先验〔分解/搜索/自验/修正〕/轨迹/回放的结构） | ✓ 结构层可迁移 |
| 定性规律（轨迹按 token 计价/报错也是数据/回放多样性优先/分布对齐>知识灌输） | ✓ 可迁移 |
| 验证纪律（matched SFT 桥/消融/去污/反作弊） | ✓ 可迁移 |
