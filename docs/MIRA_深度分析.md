## 一、核心论点

### 1.1 问题定位

中训练（mid-training）的数据选择问题与预训练和后训练都不同：
- **预训练方法**（PPL、梯度、影响估计）可扩展但只提供隐式信号——不定义"什么使一个样本在其源格式中有用"
- **后训练方法**（人类标准、偏好信号、LLM 判断）提供语义判断但假设固定标准或标准化格式——不适用于中训练异构数据

**核心矛盾**：中训练数据既有预训练式来源（网页、代码、数学、长文本），也有结构化来源（指令示例、推理链、工具调用日志、多轮 agent 轨迹），不同来源的质量标准不同，不能用单一全局 rubric 评估。

### 1.2 核心方法：自锚定 rubric 发现

MIRA 的关键创新：**把 rubric 构造本身作为数据选择的一部分**——不是预先定义质量标准，而是从数据中自动发现每个源组的质量维度。

四步流程：
1. 自锚定 rubric 发现（前沿教师模型自由评判 → 聚类锚定维度）
2. 锚定评判蒸馏（教师重打分 → 学生蒸馏，每组一个学生）
3. 源条件可靠性聚合（残差诊断 → 掩除不可靠维度 → trimmed mean）
4. 源保留选择（全局/组级/源级三级保留阈值）

## 二、方法详解

### 2.1 自锚定 rubric 发现（Section 3.2）

**源聚类**：对每个源的代表性样本做内容 embedding，按均值聚类源 → 少数能力一致的源组（实验中 5 组）。

**自由形式评判**：前沿教师模型对每组样本自由提出质量维度、打分、给出理由——**不预设 rubric**。这确保锚定维度从教师实际评估行为中产生，而非作者直觉。

**判断聚类与锚定提取**：将每个自由形式响应解析为 (维度名, 理由) 对，embedding 后聚类，每个聚类选最接近质心的点作为锚定维度。每组产生 15 个锚定维度。

### 2.2 锚定评判蒸馏（Section 3.3）

**锚定教师打分**：用每组的 15 个锚定维度重新提示教师，对更大样本集打分——每个样本在每个维度上获得 (数值分数, 理由)。因为评分空间固定，组内样本可比较。

**学生蒸馏**：前沿教师太贵，蒸馏为**组特定学生打分器**——轻量模型，对每条输入产生 15 个维度的 (分数, 理由)。每组一个学生（实验中 5 个 Qwen3.5-35B-A3B MoE 学生）。

### 2.3 源条件可靠性聚合（Section 3.4）

**残差诊断**：对每个 (源, 维度) 对，在验证集上算教师-学生 MAE 和 Spearman 相关。低于阈值的对被标记为不可靠。

**后置掩除**：不可靠维度在聚合时被零化——记录的分数只用可靠维度的 trimmed mean。**不改学生 prompt**（避免维度移除引起其余维度分布漂移），只在聚合时后置过滤。

### 2.4 源保留选择（Section 3.5）

三级粒度：
- **MIRA-Global**：全局单一阈值——最高分记录不论来源。风险：高分分布天然偏高的组被过度选择
- **MIRA-Group**（默认）：组内保留阈值——同组共享 rubric 和学生，分数校准更好。保留能力多样性同时允许组内竞争
- **MIRA-Source**：源内阈值——最强源多样性保持，但依赖更细粒度、可能更噪的源级分布

## 三、实验设置

### 3.1 中训练配置

| 项目 | 值 |
|------|------|
| 基模型 | Qwen2.5-Coder-14B (48 层, 40 注意力头, hidden 5120, GQA 8 KV heads) |
| 全量 token | 50B |
| 子集 token | 25B（半量对比） |
| 序列长度 | 131,072 (128K) |
| 全量迭代数 | ~1,490 |
| 子集迭代数 | ~745 |
| 全局 batch | 256 |
| 精度 | BF16 |
| 并行 | TP=8, PP=1, CP=4, EP=1 |
| 优化器 | AdamW, wd=0.1, (β1,β2,ε)=(0.9,0.95,1e-8), grad_clip=1.0 |
| LR | cosine 5e-5 → 1e-5, warmup 5 iters |
| 每步 token | 256 × 131,072 = 33,554,432 |

### 3.2 SFT 配置

| 项目 | 值 |
|------|------|
| SFT 数据 | 400K 指令跟随样本（所有条件固定相同） |
| 全局 batch | 512 |
| 序列长度 | 128,768 |
| Epochs | 2 |
| 精度 | BF16 |
| Loss masking | 仅 assistant 回复 token（system/user/tool token 被 mask） |
| 并行 | TP=8, PP=1, CP=1, EP=1 |
| 优化器 | AdamW, wd=0.01, cosine 5e-5→1e-5 |

### 3.3 教师与学生打分器

| 项目 | 值 |
|------|------|
| 教师 | Kimi-K2.6 (Moonshot AI), temp=0, 38K token prompt budget |

## 四、实验结果

### 4.1 主要结果

| 方法 | 代码生成 Avg | Multipl-E | SQL Avg | SWE-M | **Macro Avg** |
|------|------------|-----------|---------|-------|-------------|
| Base Model (无中训练) | 46.89 | 59.14 | 6.29 | 0.33 | 28.16 |
| + SFT only | 53.91 | 72.57 | 64.24 | 3.67 | 48.60 |
| Full Corpus (50B) | 53.71 | 67.42 | 94.18 | 40.00 | 63.83 |
| Random (25B) | 52.71 | 71.44 | 93.79 | 35.00 | 63.23 |
| DSIR (25B) | 48.74 | 67.26 | 95.20 | 27.00 | 59.55 |
| PPL (25B) | 50.52 | 57.74 | 90.66 | 20.00 | 54.73 |
| DataMan (25B) | 53.82 | 71.38 | 93.84 | 33.00 | 63.01 |
| **MIRA-Group (25B)** | **54.53** | 71.85 | 94.08 | **36.33** | **64.20** |
| MIRA-Source (25B) | 54.18 | **72.84** | **94.38** | 30.33 | 62.93 |
| MIRA-Global (25B) | 53.12 | 67.84 | 94.26 | 32.00 | 61.81 |

**关键结论**：
1. MIRA-Group 用 25B token（半量）的 macro avg 64.20 **超过** Full Corpus 50B 的 63.83
2. 比 Random（63.23）高 0.97 分，比 DataMan（63.01）高 1.19 分，比 DSIR（59.55）高 4.65 分
3. 三级变体各有专长：MIRA-Group 最优码生成，MIRA-Source 最优多语言

### 4.2 关键分析

**长度鲁棒性**（Figure 2）：
- PPL 随 token 长度急剧下降（长度偏差）
- DSIR 短记录高但长上下文区域崩溃
- DataMan 长度不敏感但无法处理超长记录（输入长度限制）
- **MIRA 在短/中/长记录上保持平滑分数**——长度鲁棒

**rubric 空间可视化**（Figure 4）：
- QA/Text/Agent 的 rubric 在 t-SNE 中占据不同区域——格式依赖
- DataMan 的 14 条标准全部落在 MIRA rubric 空间内部——MIRA 覆盖且更丰富

**可靠性诊断**：
- 37/315 (12%) 源-维度对被 mask（MAE ≥ 1）
- 9/21 源完全干净（无被 mask 维度）
- 最差：funccall_agent_b（8/15 维度被 mask，MAE 1.00）
- "Technical Precision" 是 QA 格式源最常被 mask 的维度
- 不可靠性稀疏且维度特定，非整个源/学生不可靠

**案例研究**（Figure 5）：
- 高分 Agent 轨迹：有效工具调用 → 观察错误 → 修正下一步
- 低分 Agent 轨迹：多个 JSON 对象拼接在一个参数字段 → 解析器错误 → 重复相同无效调用无恢复
- **MIRA 分数反映轨迹级正确性而非流畅度**——好坏轨迹都流畅，但工具调用结构有效性不同

## 七、与用户场景的关系

### 适配评估

| 用户需求 | MIRA 是否满足 |
|---------|-------------|
| 中训练场景 | ✅ 完美匹配（50B tokens, 128K seq, Qwen2.5-Coder-14B） |
| 半量匹配全量 | ✅ 25B token 匹配/超过 50B 全量 |
| STEM 提升 | ✅ 代码/数学为主的中训练 |
| 域级配比 | ❌ 样本级**筛选**，非域级**配比** |
| 1.5B+ 模型 | ⚠️ 验证了 14B，1.5B 未验证 |
| 开源代码 | ❌ 无 |
| 有限算力 | ✅ 学生蒸馏 <4% 中训练成本 |

### 定位：互补而非替代

| 方法 | 层面 | 与 MIRA 关系 |
|------|------|-------------|
| DIDS (#66) | 域级配比 | **互补**：DIDS 决定各域比例，MIRA 在域内做质量筛选 |
| Velocitune (#61) | 域级配比 | 互补（同上） |
| Data Mixing Agent (#63) | 域级配比 (RL) | 互补（同上） |
| BETR (#64) | 文档级过滤 | **同类**：都是样本级选择，但 BETR 用 benchmark 相似度，MIRA 用 rubric |
| DataMan (#11) | 质量评分 | **直接竞品**：MIRA 比 DataMan 高 1.19 分，且 rubric 空间覆盖 DataMan |

**理想 pipeline**：MIRA 做域内质量筛选 → DIDS 做域间配比。MIRA 先过滤掉低质量样本，DIDS 再决定各域采样比例。

### 局限性（论文自述）

论文明确承认：MIRA 只是中训练数据管理的一部分。源发现、混合比例设计、课程调度、去重、污染控制均不在范围内。未来方向是将 MIRA 集成到更广泛的数据配比优化管道中。

## 八、可信度评估

**优势**：
- 实验充分：21 源 5 组 9 benchmark，25B vs 50B token 对比
- 代码导向中训练规模匹配真实场景（50B tokens, 128K seq）
- 详尽的附录（A.1-A.7 配置完整，C.1-C.4 提示模板完整）
- 消融：三级选择粒度、可靠性 mask 分析、rubric 空间可视化
- 计算 <4% 中训练成本——实用可行
- CC BY-SA 4.0
- 机构可信（SJTU + UBC + Langboat + 北航 + IQuest）
- HuggingFace 有资源（虽然未列举内容）

**劣势**：
- 无 venue（arXiv 预印本，2026.05）
- 无代码（只有 HuggingFace collection）
- 依赖 Kimi-K2.6 教师（可能不通用）
- 学生模型 35B MoE（对用户 1.5B 规模可能过大）
- 教师打分成本未报告
- 专测代码中训练，STEM 其他子学科（非代码）未验证

## 九、相关性评级

**★★★☆☆ 中等**

中训练场景完美匹配（50B tokens, 128K seq, 代码/STEM），半量匹配全量的能力直接可用。但定位是样本级**筛选**而非域级**配比**，与用户核心需求（域间配比）不同层面。无代码、无 venue、依赖 Kimi-K2.6 教师。最佳定位是 DIDS/Velocitune 等域配比方法的**前置质量筛选步骤**——MIRA 先在域内过滤低质量样本，域配比方法再决定各域比例。
