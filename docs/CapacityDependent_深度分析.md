## 一句话总结

推翻"高似然（贴近学生分布）数据总是更优"（GRAPE, 2025）与"难样本总是更优"（active learning 传统）两个单边直觉：数据选择的价值**同时依赖学生容量与训练时长**——小模型（≤3-4B）只能吸收贴近自身分布的监督（Fast-Fit/No Catch-up），大模型（≥8B）+ 长训练下低似然数据反超（Sustained Slow-Gain Reversal）；1.5B 恰处最深度的"No Catch-up"区。

## 0. 实验设置

- **任务**：数学 reasoning SFT 蒸馏。MATH12K 数据集，两个教师（Qwen2.5-72B + gemma-3-27b-it）为每题生成多个候选回答
- **选择规则**（以 base 学生模型的对数似然为难度度量——"student-grounded difficulty"，区别于 trace 长度等学生无关代理）：
  - D_high：每题选 base 学生似然**最高**的回答
  - D_low：每题选似然**最低**的回答
- **学生**：Qwen2.5-1.5B / Qwen2.5-3B-Instruct / Qwen3-4B / Qwen2.5-Math-7B / Qwen3-8B（附录 C 加 Llama3.2-3B / Llama3.1-8B 交叉验证）
- **训练**：5 epochs，每 epoch 存 4 个 checkpoint（共 20 个）；LR 1.25e-6（极小）、cosine 衰减、无 warmup
- **评估**：10 个数学 benchmark（AIME24/AMC/CHMATH/Gaokao/GPQA/GradeSchool/KAOYAN/MATH500/Minerva/OlympiadBench），pass@1，temp 0.6

### 0.1 学生似然的定义（论文 §3, Eq.2/4/5）

自回归分解下，候选回答 y=(y₁,…,y_T) 对题目 x 的似然 = ∏ₜ πθ₀(yₜ | x, y<ₜ)；实际计算 = frozen 学生基座（θ₀=训练前）一次前向，回答 token 的 logprob **求和**。⚠️ 求和式似然使 D_high 系统性偏向简短回答（长度混淆，论文未讨论）；本文档给用户的文档过滤方案用**平均 NLL**（长度归一）避开此混淆。

### 0.2 实验设计逻辑（配对受控实验）

同题钉死、只换回答（教师对每题生成多候选）→ 学生似然推两极造 D_high/D_low（无分位阈值，测似然因素的因果效应）→ 同配置双学生分别喂两个数据集 → 5 个尺寸重复得容量模式（1.5B 死记 vs 8B 反超）——为难度选择理论增加容量轴（前两轴：数据量 Sorscher、学习阶段 Weinshall）。

## 1. 核心结果：Fast-Fit/Slow-Gain

### 1 epoch 后（Table 1，4 checkpoint 取最优）
高似然几乎全面获胜，且**模型越小优势越大**：1.5B/3B 高似然赢 ~10/10 数据集；7B 赢 8/10；8B 赢 9/10。

### 5 epochs 后（Table 2，20 checkpoint 取最优）——**容量依赖反转**
| 学生规模 | 模式 | 证据 |
|---|---|---|
| 1.5B / 3B / Llama3.2-3B | **Fast-Fit / No Catch-up** | 1.5B：1 epoch 平均 **24.16 vs 14.77**（10/10 数据集全胜）；低似然再训 4 epochs 最好 16.50 仍够不到高似然 1 epoch 的 24.16。3B 同样全胜（33.38 vs 24.63） |
| Qwen2.5-Math-7B | Fast-Fit / **Unstable** Slow-Gain | 低似然 6/10 峰值更高（46.19 vs 45.41），但 20 checkpoint 中仅 5 个时点简单平均更高——间歇性而非持续性 |
| Qwen3-8B / Llama3.1-8B | **Fast-Fit / Sustained Slow-Gain Reversal** | avg：高 66.16→66.64（+0.48）vs 低 62.62→**70.69**（+8.07）；epoch 2.25 交叉后低似然持续领先至 epoch 5。单科 5 epochs：AIME 低 43.33 vs 高 40.00、CHMATH 63.33 vs 56.67、MATH500 93.00 vs 92.00（10 科中低似然赢 9） |

三个 Observation：
1. **早期优势**：高似然早期收益快且稳，小模型尤甚
2. **晚期反转**：大容量模型高似然早峰、低似然后来居上
3. **小模型死记**：案例分析（Table 3）——1.5B 重复题干+卡在错误答案（浅层模仿）；3B 能起几步推理但陷入重复；7B 完整推理到达正确答案

### 峰值可达性 vs 持续优越性（附录 C.5，方法论自觉）
作者区分两个标准：Peak Accessibility（max_t P_low > max_t P_high）与 Persistent Superiority（交叉后全程 P_low > P_high）。7B 满足前者弱满足后者（过渡容量区，优化敏感）；8B 两者皆满足。**这是对"best-checkpoint envelope"报告偏差的自我审计**——每列独立取 20 个 checkpoint 最优值并不对应同一模型，作者主动披露并用 checkpoint 对齐比较修正。

## 2. 双视角学习动力学（§5）

**教师视角**（Gemma 似然衡量生成答案）：
- 1.5B：低似然训练后学生几乎无法靠近教师分布——**吸收失败**
- 3B：低似然数据下向教师移动最明显（受益最大的中间尺度）
- 7B：两种选择下都能对齐教师（容量足够时选择策略影响减小）

**原模型视角**（base 模型似然衡量漂移）：
- 1.5B 低似然训练 → 损失发散且大部分生成仍贴近原分布（学了个寂寞）
- 尺寸增大 → 高/低似然训练的输出分布分离更清晰、方差更小、泛化更好

Observation 4：低似然数据能把大模型拉向教师，对小模型无效。Observation 5：随容量增大，行为更稳定、选择策略效应更显著。

## 3. 理论：容量约束蒸馏（§6）

设定：二分类、线性教师 w* 与学生 w、软标签蒸馏、梯度流。

- **定理 6.1（高容量）**：w(τ) → w₀ + P_X(w* − w₀)。**数据是教师的镜子**——只有知识差距 w*−w₀ 落在数据张成空间 X 中的分量能被转移；与数据张成正交的方向永不更新（学生被初始化约束）
- **定理 6.2（低容量）**：可行参数子空间 F ⊆ R^d，w(τ) → w₀ + P_XF(w* − w₀)。**双重投影**——数据张成先投影到学生可表示子空间，蒸馏同时受"数据揭示什么"与"学生能表示什么"约束
- 附录扩展：深层线性网络（N≥2）+ 梯度空间命题 + 限制强凸性/PL 条件 + 投影数据等价定理

**Takeaway 2（容量对齐数据是低容量蒸馏的必要条件）**：似然过低 → 教师暴露的知识超出学生可表示/可优化范围 → 监督无效。这给 Fast-Fit/Slow-Gain 提供几何解释：低似然数据对大模型是"更大的镜子"，对小模型是"照不进去的镜子"。

**对既有文献的定位**（§2）：难度选择有效性此前沿两个轴刻画——数据量轴（Sorscher 2022：数据稀缺保简单、数据充裕用难的）与学习阶段轴（Weinshall 2018 课程学习）；本文新增**容量轴**。

## 4. 与本项目的系统关联

### 4.1 用户场景直接命中：1.5B
用户是 1.5B 中训练 + STEM accuracy + N=1-2 runs：
1. **T1 - 1.5B 处于"No Catch-up"最深区**：高似然在 1 epoch 和 5 epochs 都占优。**推论：用户 1.8B 中训练的 STEM 数据应偏向基座分布可及的数据，不要追求"最难/最超前"的语料**。具体可操作：用 ClimbLab 基座对候选 STEM 语料打 perplexity，偏向中低 PPL 段；避免灌入基座几乎无法建模的超难合成推理数据（如 R1 式长 CoT 直接喂 1.5B——正是"小模型死记"的典型场景）。**⚠️ 常见误读澄清（用户提问引出）**：不是用数据的**外部难度标签**（trace 长度/难度标注/来源等级）——论文核心区分恰在此：难度标签是 student-independent 代理，同一数据对 7B 够得着、对 1.5B 够不着；正确做法是 **student-grounded**：基座自己打 PPL → 直方图分位 → 保中低段、砍极高 PPL 尾部。注意极低 PPL 段可能是重复/退化数据，不是越低越好。

**⚠️ "PPL 高 = 没见过的数据 = 应该加强"——这个直觉哪里对哪里错（用户两轮追问后重写为教学版）**：

推理链拆解：`PPL 高 → 没见过 → 含新知识` ✓ 对；`含新知识 → 喂进去就能学到` ✗ 断裂处。第二步隐含假设"知识摆在面前 = 能消化"，对人对模型都不成立。类比：给小学生研究生泛函分析教材——确实全是新知识（真没见过），但结果只是抄符号背字面（死记），给五年也学不会，因为缺的中间概念（极限/线性空间/测度）这本书不补、他的知识结构里没有挂钩。"应该加强"要成立，数据须落在**最近发展区**（维果茨基）：比现有水平高一点才吸得进，高太多传不进去。

**三区间表**（对 1.5B 基座按 PPL 排开候选文档）：

| PPL 区间 | 类比 | 训练时发生什么 |
|---|---|---|
| 低（已掌握） | 重做上学期题 | 梯度≈0，浪费算力，无害 |
| **中（跳一跳够得着）** | 略高于水平的新题 | **真正学习的区间 ★** |
| 极高（够不着） | 小学生读泛函分析 | 死记表面模式，能力不涨，挤占预算 |

> **出处说明**：三区间的定性结构来自 #88（Fast-Fit/No Catch-up + 死记行为），但**切分位置（如 q0.5%/q95%）不是论文数字**——论文用 argmax/argmin 二分（同题教师候选回复间取学生似然最高/最低），无任何分位阈值。具体切分须按"计算量与实操协议"节的采样审计对各源分布形状单独定，[q0.5%, q95%] 只是"只剪长尾不动主体"的工程默认值。

- **可自行验证的现象**：喂够不着的数据，训练 loss 会降（背 token 级统计），但下游 accuracy 不动——loss-accuracy 鸿沟（Layer 5）在 PPL 极高端的具体实例。#88 Table 3 实证：1.5B 训低似然数据后复述题干+"2023 2023..."卡死（抄符号非解题）；同一数据 7B 完整解题。1.5B 训 5 epochs 仍全面落后（No Catch-up）——问题不是时间，是挂不住。
- **"该不该加强"是（数据×模型）对的属性，非数据自身属性**：同一本教材，8B 有概念脚手架 → 从第三区间移入第二区间（8B 反转实验：5 epochs avg 低似然 70.69 vs 高似然 66.64，epoch 2.25 交叉后持续领先）。这是标准 exploration 论证（active learning 难样本）对 8B+ 正确、对 1.5B 失效的原因——容量条件性。
- **宏观/微观之分**：用户 70% STEM 中训练本身就是宏观"加强没见过的数据"，成立因为 ClimbLab 基座含 STEM（STEM 文档 PPL 主体落在中区间，非无限远）+30% 通用锚定。本建议仅针对 STEM 池内部文档级过滤（砍极端尾部）。
- 极高 PPL 尾部还混杂垃圾文本（乱码/模板/退化），PPL 无法区分"新颖但难"与"纯噪声"，砍尾同时去除两者（保守但安全）。
- **域混淆警告**：不同域的 PPL 基线不同（数学文本对 web 为主的基座天然 PPL 偏高）→ 阈值必须**源内/域内分位**，不能全池全局一刀切（否则会系统性砍掉数学/代码）。ClimbLab 基座本身含 STEM，部分校准了这一点，但仍按源内分位执行。
- 先例：LM-PPL 过滤语料是成熟技术（CCNet 用小 LM 打分过滤 CommonCrawl，保留中段），本文的增量是"以**学生自身**为打分器 + 容量条件性"。
- 诚实边界：#88 证据来自 response 级 SFT 选择，corpus 级文档过滤是**类比外推**（方向可信、幅度未知），且 1.8B 中训练尺度下建议只砍极端尾部、不做激进过滤。

**⚠️ 用哪个模型打分（用户追问引出）**：**用 1.5B 基座**（= 你自己的中训练起点 checkpoint，即"ClimbLab 基座"），不是 400M 代理模型。理由：student-grounded 原则——要测的是"**这个**学生能不能吸收"；400M 的吸收边界更小，对一切数据 PPL 系统性偏高，会**高估难度**，用 400M 给 1.5B 选数据正是 Puro 0.6B→2B 那个容量错位陷阱（见 #84 交叉引用）。400M 代理若用于配比搜索（RegMix 式）属另一条线，其迁移 gap 已有记录。

**⚠️ 计算量与实操协议（用户追问引出）**：PPL 打分 = 纯前向（≈2ND FLOPs，训练≈6ND），同 token 数约为训练 1/3 计算量且可大批量推理。但**全池逐文档打分不便宜**：10B tokens 候选池×1.5B 模型 ≈ 3e19 FLOPs ≈ 约 2 倍于你整个 1.8B 中训练 run——不要全打。**采样式协议**（镜像 Puro 的切片逻辑）：决策是源级/阈值级 → 每源随机抽 1k-10k 篇文档 → 得各源 PPL 分布 → 源内分位定阈值 → 只对将重度使用的源做逐文档打分（可选）。成本降到一次 run 的百分之几。若直接消费 ClimbMix（已策展）则完全不需要这套。
2. **T2 - N=1-2 约束下的时序解读**：高似然早峰、低似然晚反超——若用户只跑 1-2 个 run 且训练预算有限，"低似然数据需要长训练才回本"意味着**短预算下高似然是更安全的选择**（与 5-epoch 反转结论不矛盾：反转需要容量 ≥7B 且 20+ checkpoint 的长训练）
3. **T2 - Student-grounded 难度定义**：难度应该用学生自身似然定义而非 trace 长度等外部代理——与本项目"代理不可解性"主题（Layer 4）同向：任何学生无关的难度代理都忽略了"该学生能否吸收"
4. **T3 - 容量轴进入选择理论**：域配比搜索（RegMix 等 proxy 方法）隐含假设"好数据跨容量不变"；本文证明至少对似然维度这不成立——**proxy 模型容量与目标模型容量差距本身是选择信号的混杂变量**

### 4.2 场景差异（不可直接迁移）
1. **SFT 回答选择 ≠ 中训练语料配比**（四维差异，2026-09-02 追问后细化）：
   | 维度 | 本文 | 用户场景 |
   |---|---|---|
   | 数据本体 | 教师生成的推理 trace（内容天然对准 eval 分布） | 原始文档（ClimbMix 组件，异质网页/教科书/论文） |
   | 选择单位 | **同题不同回答间配对选择**（题目钉死，单变量隔离） | **不同文档间过滤**（难度与内容混杂；低 PPL 可能是 trivial/重复，高 PPL 可能是噪声也可能是新知识） |
   | 训练方式 | SFT：12k 样本、LR 1.25e-6、5 epochs | continual pre-training：1.8B tokens、中训练 LR 量级 |
   | 比较结构 | D_high vs D_low 两个数据集的对决 | "池内哪些文档进/不进"的过滤决策 |
   因此 **+9.4 pp（1.5B 1 epoch avg 24.16 vs 14.77）是配对蒸馏实验的效应大小，不能搬为"文档池按 PPL 过滤能赚 9 个点"**；可迁移的只有方向性结论（1.5B 从够得着的数据学得多、够不着的数据学成死记），收益大小在原始文档过滤场景**无人量化过**，要测本身就是一个小实验（采样审计→过滤组 vs 未过滤对照）
2. **规模**：MATH12K×5 epochs 的小尺度 SFT；LR 1.25e-6 极小 regime；1.8B token 中训练的动态可能不同
3. **1.5B 用的是 Qwen2.5-1.5B（非 Instruct/Math 特化）**，且学生在数学 SFT 前 base 已有数学能力——"从强 base 中训练"与用户 continual pre-training 有一定对应，但分布匹配的计算方式（响应级 argmax 似然）在语料级需换成 PPL 分位
4. **理论局限**：二分类线性模型，离 LLM 蒸馏很远；只提供几何直觉不提供定量预测
5. **AIME/GPQA 评估集极小**（30/99 题），单格数字噪声大（1.5B 行 AIME 3.33 vs 10.00 = 1 题之差，是 Table 1 中高似然罕见的输项但不足为据）
6. **argmax 求和式似然的长度混淆**：D_high 偏向简短回答（见 §0.1），容量效应与长度效应未完全解耦

### 4.3 对本项目框架的增量
- **五层困难的 Layer 4（代理不可解）新增实例**：proxy 信号的容量依赖性——0.6B proxy（Puro）与 1.5B 学生（#88 理论）之间的容量错位是配比信号失真的又一来源
- **与 #84 Puro-2B 直接对话**：Puro 用 Qwen3-0.6B proxy 选数据喂 2B 模型；本文证明数据选择价值随容量反转——Puro 的 proxy 决策在 2B 上是否仍是好决策未被检验，这是两篇拼起来暴露的开放问题
- **与 #71 DomainRepetition 对话**：域级最优重复与 val loss 负相关；本文补充"什么样的数据值得重复"——高似然（可吸收）数据
- **与 MobileLLM-R1 对话**：R1 的 influence→0 信号（梯度内积）在容量小的模型上天然更弱（吸收失败→梯度信号弱）——LR confound 之外的第二个 confound 候选

## 5. 局限性汇总

1. 单数据集（MATH12K）单任务域（数学）；未见代码/常识/多域验证
2. "Best across checkpoints" 报告口径（作者已自我审计但主表仍是 envelope）
3. 理论设定（二分类线性 + 软标签）与实验（LLM + 硬 SFT）之间距离大
4. 教师只有 2 个；候选池多样性有限（每题 J_T 个回答）
5. 未检验中间策略（如似然分位混合、课程式从高到低）；只有两个极端 D_high/D_low
6. 容量与"模型代际/预训练数据量"混杂（Qwen2.5 vs Qwen3 混用，7B 槽位是 Math 特化模型）——Llama 交叉验证部分缓解但不能消除

## 6. 评估
