# 核心未解决问题：相变前的信号能否预测相变后的最优配比

> 本文档综合所有论文的分析，聚焦一个贯穿全局的核心问题：**在能力涌现的相变之前，能否预测相变之后的最优数据配比？**
>
> 这是 QuaDMix 失败的根因，也是 LogFloor (#68) 暴露但未解决的桥，更是整个数据配比领域的理论瓶颈。

---

## 一、问题定义

### 1.1 核心问题

给定：
- 一个有 phase transition 的能力（如 STEM accuracy，在 ~1.5B 涌现）
- 一个小 proxy 模型（如 14M/70M，**在相变之前**）
- 一个 target 模型（如 1.5B，**在相变之后**）

问：能否从小 proxy 模型的训练信号中，预测 target 模型的最优数据配比？

### 1.2 为什么这是一个独特的困难

Phase transition 意味着：在相变点之前和之后，模型的行为发生质变——不只是量变。

- **相变前**：模型 loss 在下降，但 accuracy 不变（还没"学会"这个能力）
- **相变后**：模型 loss 快速下降， accuracy 跃迁（"学会"了）

问题在于：相变前的 loss 下降模式（哪些域快、哪些域慢）和相变后的 accuracy 涌现模式可能完全不同。**相变改变了难度层级排序**。

### 1.3 三道门分解（2026-09-15 讨论沉淀，源自 Marin 535B 调研 §8.5）

"相变"实际上是**三道不同轴上的门**，混为一谈会误判安全区：

| 门 | 轴 | 含义 | 用户场景状态 |
|---|---|---|---|
| **门1 知识获取阈值** | 数据配比 r | r 低于 r_thres 时 STEM 知识根本进不去（白喂）；#01：r_thres ∝ M^(-α) | 1.5B r_thres≈0.06-0.08，r=0.7 远过 ✓ |
| **门2 走完相变的训练量** | tokens/步数 | 过门1 只是"开始学"；#01：所需步数在 r<0.4 时随 1/r 超指数增长，r=0.7 属便宜区间 | 便宜区间 ✓，但 1.8B 预算是否走完**无法先验计算** |
| **门3 accuracy 起跳点** | 能力涌现 | 知识装入 ≠ 会做题：loss 可平滑下降而 benchmark 长期趴零，到某点才起跳 | **位置未知——本文档的核心问题本体** |

**推论**：
1. "r=0.7 已过阈值所以安全"只对门1 成立——门3 无人替你考虑（Marin 也没有：他们停在 loss，535B 对其所测技能早已全过门3）
2. 门2/门3 **只能测不能算**：训练中途定期评 benchmark（不只终点），**把起跳时机本身记录下来**——它比最终分数信息量更大（直接回答"1.8B 预算买到没有"）
3. MiniCPM5 Base→Midtrain diff 定标（#102）是门3 的经验锚（工业界 2B mid-training 涨了多少）
4. 任何"平滑饱和"形状的公式/代理（DSP 族、标准核 GP、树模型）**结构上表示不了门1/门3 的跳变**——只能用于远离阈值的局部插值，不能跨 regime 外推；这是小 proxy 不可靠的形状学解释之一（14M 在门1 之下、1.5B 在门1 之上，两者曲线形状根本不同）。跨 regime 只带锚点（1.5B 实跑验证点）不带公式
5. 新增独立证据：Marin qsplit240 swarm 实测 **60M→300M identity transfer Spearman 仅 0.777**（其 research.md），加上 60M@22% 进度 0.298——proxy 跨尺度名次不可靠的第三来源（另见 `小Proxy不可用_多论文交叉验证总结.md`、`Marin535B_Harrier_深度分析.md` §8.5）
6. 再增两条独立证据（2026-09-18，详见 §2.9）：① AutoData（#111）实测 125M-1.3B 尺度 CORE（22 任务）所有配比/选择比较**全不显著——即使直接以 accuracy 为搜索目标**，且 proxy 发现 897M 有效→1.3B 归零（小效果代理迁移上限 ~1B 的同栈数据点）；② 2609.18960 受控重放：选择器"审计质量排名 vs 下游效用排名"Spearman ρ=0.04（中位数 0.00，五选择器全错位）——跨领域（低资源分类非预训练）但协议最狠的一条
7. 重复率失配（#124 Repetition Mismatch，2026.10，详见 §2.11）——外推失败的**第四种解释，独立于模型尺寸**：各源每 epoch 数随预算变、最优配比随之漂移（重复有递减收益）；同尺寸 1.17B 小预算→全预算外推同样失败。**修复廉价**：子采样匹配目标重复率后 1/16 tokens 即恢复最优配比（误差 0.10 vs 0.85）——400M proxy 线实验设计必须先修这个，再谈相变/容量那些修不了的

## 二、各方法的应对策略与失败分析

### 2.1 静态配比搜索（QuaDMix / DoReMi / RegMix）

**策略**: 用小 proxy 搜静态最优配比，迁移到 target。

**失败机制**:
- 14M proxy 的 r_thres ≈ 0.30+（STEM 相变阈值高）
- 1.5B target 的 r_thres ≈ 0.06-0.08（相变已过）
- 两个模型处于**不同 regime**：14M 在"远未跨阈值"区，1.5B 在"已跨阈值"区
- 最优配比方向相反：14M 最优"少给 STEM"（远未跨阈值，给太多浪费），1.5B 最优"多给 STEM"（已跨阈值，越多越好在线性区）
- 结果：QuaDMix gsm8k R²=0.751（within-model 有信号），但 QuadMix（应用到 1.5B）反而最差

**LogFloor (#68) 的独立验证**: 消解实验显示静态 marginal mixture 只保留 10.3% 收益（vs 正确顺序 60.3%）——静态配比即使在同尺度内部也不是关键信息。

### 2.2 动态顺序迁移（LogFloor）

**策略**: 用小 proxy 搜动态瓶颈顺序（非静态配比），迁移到 target。

**成功条件**: "难度层级跨尺度不变"——数学比代码难在 70M 成立，在 12B 也成立。

**为什么在 STEM 场景可能失败**:
- 70M 在数学域：loss 线性下降（慢速进步型），看起来是"瓶颈"
- 12B 在数学域：可能突然跃迁（loss 快速下降），不再是"瓶颈"
- **难度排序在相变点前后重排**，破坏尺度不变性

**关键缺口**: LogFloor 用 loss 不用 accuracy，绕过了"accuracy 何时涌现"的问题。但 loss 下降顺序 ≠ accuracy 涌现顺序——这个桥论文没有搭，也恰好是 QuaDMix 撞的墙。

### 2.3 域级 loss 引导（DomainPilot）

**策略**: 不用 proxy，直接在 target 上测域级 loss，拟合 power law，调整配比。

**绕行方式**: 完全绕过 proxy→target 迁移问题，在 target scale 实时操作。

**遗留问题**: loss ≠ accuracy。域级 loss 下降快不等于该域 accuracy 高。Nexus (#51) 已证明同一 loss 差 15 分。

### 2.4 理论预测（Phase Transitions / CAMEL）

**策略**: 用理论公式预测相变阈值。

**能做到的**: 预测**相变何时发生**——r_thres ∝ S/M^α，给定 M 和 S 可以算出 r_thres。

**做不到的**: 预测**相变之后什么配比最优**——理论只给出"跨阈值"的条件，不给出"跨阈值后怎么配最好"。知道 r_thres=0.06 不等于知道 r=0.3 和 r=0.5 哪个更好。

### 2.5 贝叶斯域重加权（Bayesian Domain Reweighting, #69）

**策略**: 不用 proxy 函数拟合，从 Dirichlet 分布 + Gamma 先验直接推断域权重。

**批评现有方法**: "strong structural assumptions, such as rank invariance or scaling laws, which are often violated"——直接指向 QuaDMix/DoReMi 的结构假设。

**预期局限**: 直接优化方法绕过了 proxy→target 迁移，但本质还是用 loss 信号优化。如果 loss ≠ accuracy，贝叶斯方法找到的 loss 最优配比也可能不是 accuracy 最优。

### 2.6 benchmark 直接引导（BETR / Data Mixing Agent）

**策略**: 用 benchmark 分数（而非 val_loss）作 reward，绕过 loss ≠ accuracy 问题。

**能做到的**: 直接优化 accuracy 相关指标，不绕弯。

**代价**: BETR 是文档级选择（非域级配比）；Data Mixing Agent 需 1996 GPU 小时一次性成本（384 轨迹）。不适合 1-2 run 的场景。

### 2.7 工业级 forecasting 的崩溃与补救（MAI-Thinking-1 #73，2026.08）

**事件**: 微软在 §2.5.2 用几千个 760M-4B proxy 模型做 RegMix 式配比 forecasting，某代模型中发现 **rank non-invariance**——stem-heavy-mix 在小尺度 STEM NLL 上领先 code-heavy-mix，但两条曲线在 23B×20T 训练**中途交叉**，code-heavy 最终反超。归因：两个高质量 STEM 源（11.8% vs 0.3% 权重差）模糊重复多、多样性差——小模型高估其价值，大模型下多样性不足致命。

**意义**: 这是 rank invariance 假设（RegMix 理论根基）被**工业级一手实验否定**的最强实例——proxy 信号不仅噪声大（CAMEL 系列），**信号本身随规模改变符号**。且反转出现在 23B/20T 量级才暴露，说明小尺度验证点不足时该问题几乎不可见。

**微软的补救（非解决）**: 不放弃 proxy，升级协议——所有消融在 scaling ladder（恒定 TPP 多尺度曲线）上跑，重点看候选混合的 **scaling 行为**而非固定尺度排名；最终候选在 2.8× 计算量上验证直到"最优候选不再随规模变化"。代价是每个决策的验证成本大幅上升，且承认"端到端 scaling 行为仍是开放问题"（§2.5.3 结尾原话）。

**对本项目的启示**: 用户 400M→1.5B 的尺度差（3.75×）与微软 5B→23B（4.6×）同数量级。任何 400M proxy 给出的配比结论，在 1.5B 主 run 前至少要一个中间验证点确认趋势不反转；N=1-2 预算下这是 proxy 线的最低安全协议。

### 2.8 小模型 loss 信号的校准方案（MiniCPM ScalingBench，2024 提出/2025.06 TR 复用，⚠️ 偏旧）

**方法**: MiniCPM 风洞（ModelTunnel）面对同款问题——几百 M 小模型在下游任务上接近随机，accuracy 直接测不可用。解法 ScalingBench：从下游任务验证集构造评测集，强模型（GPT-4o）为每题生成推理步骤，测模型在"题干→解题轨迹"上的**条件 NLL**（不是原始预训练 loss）；该 loss 与下游 performance 呈稳定 **sigmoid 关系**（0.36B-4B 拟合，7B/80B 作外推测试点全部吻合）。

**意义**: 给"400M proxy 没有 accuracy 信号"提供了**目标信号的替代方案**——不是让小模型做对题，而是测它对标准解题轨迹的似然。条件 NLL 在用户 nanochat 栈可直接实现（token 级 loss 已支持），无需生成采样；sigmoid 映射还提供 loss→期望 accuracy 的绝对校准（区别于纯相对比较）。

**限制（三条都重要）**:
1. **偏旧**：方法 2024 年提出（Xiao et al.），TR 2025.06 复用，距今 15 个月——最新认识可能已变；#97（Qwen3.8-Next，2026.08）刚给出 loss≠accuracy 解耦的新数据点（n-gram 词表 loss 单调降而 accuracy 饱和），sigmoid 映射在当代模型上的有效性未复验；
2. **sigmoid 是跨尺度校准，不是跨配比保证**：拟合在跨模型/跨尺度上成立，但不同配比候选间的 loss 差能否保序到 1.5B 仍是 §2.7 的 rank non-invariance 问题——ScalingBench 只解决"小模型没有信号"这一层，不解决配比 rank 迁移；
3. **轨迹质量依赖**：条件 NLL 信号的上限 = 生成轨迹的强模型质量；原方案用 GPT-4o，用户须换强开源模型自建轨迹库（一次性成本，质量未验证）。

**业界认可度调研（2026-09-14，S2 引用列表 + HF 页面）**: 出处为 Densing Law of LLMs（arXiv 2412.04315，2024.12，THU+ModelBest，无正式 venue）。① **方法家族是业界主流**——论文自述 "Inspired by Llama-3"，两步 loss→accuracy 映射是 Meta 工业标准做法，RegMix（benchmark NLL 做配比回归目标）同族且在配比圈被广泛采用——信号家族本身有头部实验室背书；② **具体实现认可度中等偏弱**——52 引用/21 个月（2025:24、2026:27，持续但非有影响力），且引用构成绝大多数是"能力密度每 3.3 个月翻倍"头条结论的动机引用（跨领域泛引），**方法学采用者几乎只有 OpenBMB/ModelBest 自家生态**（MiniCPM4 TR 复用、VoxCPM2 TR 2026 引用）；HF 19 upvotes；③ **条件 NLL on CoT 轨迹这一差异化技巧无外部系统性复验**；2026 年整体风向对 loss→accuracy 映射更谨慎（#97 解耦数据点、#73 rank non-invariance）。**定位修正**：不是"偏旧旁技"，而是"Meta 验证过的信号家族 + OpenBMB 内部用 15 个月的具体实现，但外部零复验"——若激活，家族背书让方向可信，实现两步（sigmoid 校准、CoT 轨迹）必须先在自己栈上小规模复验。

**对本项目的启示**: 400M proxy 线的比较信号可从"near-random accuracy"换成"STEM 解题轨迹的条件 NLL"（相对比较用途）；sigmoid 绝对映射暂缓——先在自己栈上小规模复验 loss-accuracy 关系是否成立再用。**用户判断（2026-09-14）：有价值但偏旧，标记为参考线，不作为当前主路径。**

### 2.9 代理反馈搜索的边界实测（AutoData #111，2026.09）与审计排名失灵（2609.18960）

**方法**: AutoData（Weco AI+UvA）用 LLM agent 在"可执行选择算法"程序空间搜索（对照 RegMix/DoReMi 的权重空间），搜索反馈=125.8M nanochat proxy（0.42B tokens、固定子样本 4 种子并行）的平均 val-bpb 或 CORE；底座与用户栈同构（nanochat GPT-2 + ClimbMix 全池选 2.6%），200 步×3 LLM×2 目标=1200 候选。

**结果（两条都直接命中本文档核心问题）**:
- val-bpb 搜索有效但效果量仅 ~0.1% 相对（d8-d20 对 random/DCLM/PPL/RegMix 显著）——loss 轴在 proxy 尺度有**微弱但存在**的分辨率
- **CORE（accuracy）轴全灭**: 所有方法间差异 0.5-1.2pt 顶着种子 σ 0.3-1.3pt，无一对显著——**包括专门以 CORE 为搜索目标的那次搜索**（其冠军配方 Algorithm 2 同样不显著）。125M-1.3B 尺度上 accuracy 信号要么不存在要么噪声主导——"门3 只能测"在选择/配比场景的直接实验复现
- proxy 迁移实测: 125M 发现的配方 897M 仍显著有效、**1.3B 归零**——小效果的代理迁移上限 ~1B，与 §2.7 微软"小尺度验证点不足时问题不可见"互证

**2609.18960（When Audit Quality Fails to Predict Downstream Utility）**: 受控重放（4 种非洲语言×2 分类任务×5 同预算选择器），合成数据选择器的"LLM 审计质量排名"与"下游 Macro-F1 排名"完全脱钩——Spearman 均值 0.04、中位数 0.00。跨领域证据（低资源分类、合成数据选择，非预训练配比）但协议干净：**代理指标排名不预测下游排名**在又一场景下成立。

**对本项目的启示**: 与 §2.7/§2.8 合并，"小 proxy 只能淘汰、不能排名"现在有四层实测支撑：微软 rank 反转（23B 才暴露）、Marin 0.777、AutoData CORE 全灭（连直接优化 accuracy 都不行）、ρ=0.04（跨领域）。400M 海选的职责边界由数据划定：抓大回退可以，精细排序是自我欺骗；~0.1% 量级的效果在 proxy 尺度物理不可见——arm 之间必须设计大步差异（r 大跳跃），微调权重连测的资格都没有。

### 2.10 checkpoint 粒度的模式跳变（Generalization Dynamics #114，2026.09）

**现象**: OLMo3-7B/32B+Apertus 全部公开中间 checkpoint 扫描（9-90× Chinchilla 预算排除欠训练；仅取通用预训练段排除数据重排混淆）发现 **mode-hopping**——泛化行为在相邻 checkpoint 间突发翻转：OLMo3-32B "answer+1"（示范答案呈递增模式、测试题打破该模式）评测 2.17T tokens 81%→2.19T 0%→2.21T 81.7%；同批 checkpoint 的预训练 loss 与 10 个常规 benchmark（情感/主题/数学应用题/知识 QA）全程平稳。六个泛化指纹评测（翻转标签/重复答案/连续答案/似真 vs 真/System1-2/多人格 QA）+两个微调泛化测试一致；emergent misalignment 的效应方向在相邻 checkpoint 间反复变号（同一不安全代码 SFT 让某些 checkpoint 更错位、另一些更安全）。

**三个零假设被系统性排除**: ① 通用评测噪声（常规数据集平稳+答案区间概率直接比较排除指令跟随混杂）；② 指标选择假象（Schaeffer 式——软概率轴、FLOPs 轴上跳变仍在）；③ 标准优化动力学（edge of stability/river valley——加载 Adam 状态做单步梯度扰动不改变行为（LR 1e-2 亦然）=局部稳定；K=5 checkpoint 平均只缓解不修复）。

**解读**: 容量分配问题——容量受限模型中泛化回路必须与训练早期学到的浅回路竞争，**每个预训练数据窗口决定谁赢**。作者小规模验证（32B 续训）：按泛化相关性选的数据子集可定向稳定动力学，随机数据继续跳变——数据构成不仅影响分数，还影响能力的稳定性本身。

**与本文档核心问题的关系**:
1. **单 checkpoint 读数不是训练运行的稳定属性**——泛化敏感指标上相邻 checkpoint 天壤之别，"测一次就下结论"在泛化轴上不成立；同 checkpoint 的泛化行为跨数据集相关也低（单探针不可外推）。**注意边界**：常规 benchmark（用户 STEM accuracy 属此类）显示全程平稳——跳变威胁的是泛化敏感探针，不是标准评测
2. **与 §1.3 推论 2 互证**（门3 起跳时机比终点分数信息量大）：checkpoint 选择本身是隐藏杠杆——4.5T 中间 checkpoint 经相同 post-training 后 GPQA 36.3% vs 最终 4.9T 的 29.8%、prefilling 鲁棒性 53% vs 21%：**继续预训练/中训练改善 in-distribution 性能但不改善（甚至损害）泛化与对齐**——"训练更久/更多"与"泛化更好"解耦
3. **数据窗口→泛化动力学**的因果小实验是"数据构成影响能力形态"的微观版证据，连接 §2.4 相变理论的"数据决定什么被学会"但把粒度细化到窗口级

**相关新证据（#113 Conditional Transfer，2026.10）**: 同尺度（非 proxy）下 loss 信号指错方向的受控反例——Ado 按"loss 可减性"在线调度配比，5k 步内把下游迁移最优的目标对齐源压到 <5%，落后匹配固定混比 2.4-11.0 pp；1k 步规划视界的时间近视（~88k 步才回摆）。"loss 可减性 ≠ 下游迁移"与 #51/#97 构成同尺度三层证据，独立于 §2.9 的跨尺度 proxy 不可靠四层证据。

### 2.11 重复率失配：外推失败的第四种解释，且可修复（Repetition Mismatch #124 + 重复轴 #123/#125，2026.10）

**机制**: 各数据池的"每源 epoch 数"（重复率）随训练预算变化——预算小时高质量小池可能只走 0.x epoch，预算大时同一池被迫重复多 epoch。重复有递减收益（#123：重复代价 ∝ z=(R-1)N/U 单变量定律；#125：有效复用率 E(K,N) 在 K 大时饱和），因此**最优配比本身是"各源当前 epoch 数"的函数**——小预算实验的最优配比与目标预算系统性错位，且小实验根本看不见这个变量（它默认池子无限大）。

**证据（EMNLP 2026 Main，Imperial College London）**: 两源设定（有限高质量+web crawl）下，把数据子采样到目标重复率再用 1/16 目标 tokens 训练，1.17B 模型恢复全预算最优配比（误差 0.10；不控制则 0.85）；不受控达到同精度需 19%/44%/94% 目标预算（2/3/4 个视界）；三源 757M 两次受控视界即恢复。核心论断："是重复动力学而非规模本身决定小实验是否可泛化；数据重复应作为配比优化的一等公民变量"。

**与前三种失败解释的关系**:
- 前三种：①相变阈值随 M 移动（§4.2）、②容量竞争（§4.3/#38）、③checkpoint 级跳变（§2.10）——都作用于**模型尺寸/状态轴**
- 重复率失配作用于**预算轴**，与模型尺寸正交：#124 实验是同尺寸（1.17B）小预算→大预算外推，同样失败
- 关键区别：**可修复**。前两种是信息论/机制层面鸿沟（§四），重复率失配只需在实验设计里子采样匹配——是外推失败成分里第一个有廉价修复方案的
- 修复之后剩下的才是真难度（相变+容量+噪声）——先修这个，400M proxy 线的可信度上限才见分晓

**对用户场景的直接映射**:
1. **400M proxy 搜索线实验设计修正**：每个配比实验把各池子子采样到与 1.8B 目标预算相同的每源 epoch。例：r=0.7 下数学池 1.26B token 在 1.8B 预算走 ~1.4 epoch；proxy 预算若 1/16 且不子采样，数学池 epoch 变 ~0.09——重复动力学完全不同，搜出的配比**机械地**不可外推
2. **重复预算上界有三个独立参照**：#125 E(K,N)（大数据集更耐重复、强凸 Θ(log N)；直接修正 Muennighoff "≤4 epoch 无差"——#13 的引证源，固定倍数不是普适常数）、#123 多 epoch 定价几何（14M-2B 八尺寸扫描，2B 达用户量级）、#73 MAI NLL<0.01 记忆化 epoch capping（8× 上限）——同根轴三来源
3. **与门2 交叉**：预算不只是总 token 数，还是"各源 epoch 分布"——budget 的参数化应携带 per-source epoch（配比 × 池大小 × 预算三者联立）

**边界**: ⚠️ 两/三源简化设定、Wiki-Text 目标域非 STEM、757M-1.17B 中小规模验证；但机制本身可解析计算（每源 epoch = 预算×权重/池大小），不依赖规模外推，可信度高于一般小规模结论。

| 方法 | 用 proxy？ | 用 loss 还是 accuracy？ | 处理 phase transition？ | 核心问题 |
|------|-----------|------------------------|------------------------|---------|
| QuaDMix / DoReMi / RegMix | 是 | loss | 不处理 | proxy 最优 ≠ target 最优 |
| LogFloor | 是 | loss | **绕过**（用无相变任务） | loss 顺序 ≠ accuracy 涌现顺序 |
| DomainPilot | 否 | loss | 不处理 | loss ≠ accuracy |
| Bayesian Reweight | 否 | loss | 不处理 | loss ≠ accuracy |
| Phase Transitions / CAMEL | — | — | 预测阈值但不预测配比 | 知道何时涌现≠知道怎么配最优 |
| BETR / Data Mixing Agent | 否/混合 | accuracy | 不需要（直接优化 accuracy） | 成本高或不做域级配比 |

## 四、为什么这个问题可能根本无法解决

### 4.1 信息论视角

相变后的最优配比可能依赖于**相变后才会出现的表示空间结构**。如果这个结构在相变前不存在或不可观测，那任何基于相变前信号的方法在信息论意义上都不可能成功。

这不是"我们的方法还不够好"的问题，而是"信号不存在"的问题。

### 4.2 Phase Transitions 理论的暗示

Phase Transitions (#01) 的核心发现是相变是**尖锐的**（不是渐变的）：

- r < r_thres 时，训练再久 accuracy = 0%
- r > r_thres 时，accuracy 快速上升

如果最优配比在相变前后发生质变（从"不需要给太多"到"越多越好"），而相变点本身依赖于 M（模型大小）和 S（知识总量），那么：

- proxy (小 M) 的 r_thres 很高 → "少给"看起来最优
- target (大 M) 的 r_thres 很低 → "多给"最优
- proxy 的"最优"信号与 target 的"最优"信号方向相反

### 4.3 Capacity Competition 的解释

Explaining Data Mixing Scaling Laws (#38) 从理论上解释：有限模型容量在域间分配，导致域 loss 全局耦合。proxy (小容量) 的容量竞争机制与 target (大容量) 完全不同——14M proxy 容量极稀缺，必须"放弃"稀有复杂域（如 STEM）来优先学高频简单域；1.5B target 容量充足，可以同时学。

这意味着：proxy 和 target 的最优配比**必然不同**，不是噪声问题，是机制问题。

### 4.4 Why Larger Models Learn More 的实证

#52 直接观察了这种现象：小模型把神经元分配给高频/低复杂度域，稀有复杂域被牺牲。这不是"小模型学得慢"，而是"小模型学不了"——容量不够时优先级排序本身就不同。

### 4.5 动力学视角：val loss 平滑而能力永不点燃（Kinetics，2026.07，#139）

Lei Dong（独立研究者单作者，arXiv 2607.27281——⚠️ **当假说源不当证据源**）提出驱动成核速率定律：能力形成=电路所有零件一次随机对齐的"无部分学分"事件，速率 = sites×attempts×drive×exp(−βK) − destruction（K=缺件数，等待时间随缺件数指数增长）。两个与本项目直接相关的推论（均预注册+冻结常数）：

- **浓度门槛点燃**：基线持平的能力，在数据混合过了浓度门槛后于选定步点燃——门槛上 10/10 点燃、门槛下 0/12。这是 #01 相变 r_thres(M) 的动力学语言重述：门槛不是"平均效应累积"而是"稀有对齐事件的速率常数"。
- **监控盲区**：反向解读（plasticity loss）——等待过临界步后能力**永不点燃**，而**验证 loss 全程平滑下降**（原文："standard monitors are blind to it"；损伤定位=heads commit to base data）。这是"门3（accuracy 起跳点）只能测"的机制论证：val loss 对能力不可学**无分辨率**，不是测量噪声问题——与 §2.7 MAI forecasting 崩溃、§2.10 mode-hopping（常规 benchmark 平稳而深层能力跳变）同谱系但给出了成核机制解释。

**值得注意的张力**：该工作同时声称**点燃前可从 precursor 以 5% 中位误差预测到达时间**（六个 held-out 模型）。若被独立复现，这是"相变前信号预测相变后"的第一个正面线索，与 §4.1 信息论论证正面冲突（信号可能存在于相变前的 precursor 中）。当前证据级别（独立研究者单作者、主证据为 Pythia 消融）不足以裁决，标记为假说源持续追踪——**后续任何"proxy 信号预测涌现"的论文都应对照此框架检验其信号是否为 precursor 类**。

（关联：#135 RGI——域间相对损失差是数据敏感、优化器不敏感的信号，其对点燃/不可学是否有分辨率待验证；§1.3 门3 的"中途定期评 benchmark 记录起跳时机"在此框架下=采样点燃事件本身。）

## 五、对项目的实际影响

### 5.1 不可能做的事

**从小 proxy 预测 1.5B 的 STEM 最优配比** — 这条路在理论上有根本性障碍。无论用什么方法（回归、贝叶斯、顺序迁移），只要信号来自相变前的小模型，就不可能可靠预测相变后的最优。

### 5.2 能做的事

| 路径 | 方法 | 代价 | 风险 |
|------|------|------|------|
| **在 target scale 操作** | DomainPilot（域级 loss + power law 拟合） | ~30 行 patch + 1 run | loss ≠ accuracy |
| **直接优化 accuracy** | BETR（benchmark 相似度过滤） | ~2-4 GPUh | 文档级非域级，需串联 |
| **用 heuristic 而非预测** | quality-top-k + rarity | 低 | 不保证最优 |
| **接受不可预测** | Random + Fixed-ratio 基线，不做配比优化 | 0 | STEM 可能差 |

### 5.3 核心判断

> **QuaDMix 的失败不是 bug 而是必然。** proxy 搜索路径（无论静态还是动态）在有 phase transition 的能力上不可迁移，这是信息论层面的鸿沟。
>
> 所有论文要么选择不需要预测的场景（LogFloor 用无相变任务），要么用 loss 绕开 accuracy 涌现（DomainPilot），要么用 target 信号在线调整（但这不是"预测"而是"反应"）。
>
> **这个鸿沟目前没有任何论文跨越。**
